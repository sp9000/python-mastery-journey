### Quick checklist before you hit "Create pull request"

- [ ] Title follows conventional commit style or at least is very clear
- [ ] Description contains **Why / What / How-to-test** sections
- [ ] Linked at least one issue (the gotchas one)
- [ ] Self-reviewed the diff (look at changed lines in the "Files changed" tab)
- [ ] Added 2–4 review comments on your own code/notes (as practice)
- [ ] CI / Actions is green (or at least no new red items appeared)

Once the PR is created, you can immediately merge it yourself (since it's your repo) or leave it open for a day or two so you can keep force-pushing small improvements to it.

Let me know if you'd like a slightly shorter / more minimal version or a version that emphasizes different aspects (more focus on the project code changes vs. the notes).
